## Result
"Doctor" in the project bar checks the planning files and lists duplicate ids, missing ids (filename or frontmatter), id mismatches, broken links, missing images, frontmatter errors and untraced tasks, grouped by kind, each with `file:line` that opens the editor at the line. Task files include the archive's month folders. Links are checked in the planning root and wherever they point into it; `templates_dir` is skipped. Obvious fixes (write the filename id, rename to an id filename or a new id for a duplicate with links following, repair a link by id) are offered with "Fix…" and run only after "Apply"; each is checked again and written against the text read.
- `npm run check` passes (tsc, biome, 337 tests); `cargo test` (253 passed, 1 ignored) and `cargo clippy --all-targets` are clean.
- Tested in Rust: every kind with its line on one fixture, which fixes are offered, `SetId` changing only the `id` line and refusing a stale fix, a rename giving a new id with links following and never writing over a file, a repairable link with its repair. The phase 3 exit test (`phase_3_exit_zero_findings_on_a_generated_project`) builds a project with init, Make task, board moves, the archive (two month folders) and a merged git branch, 240 task files, follows each move with the watcher's link rewrite and gets zero findings; without that rewrite it does report the broken links. Run once on this repository: zero findings in 67 task files.
- Not tried in the running app: the panel layout, opening a finding at its line, and applying a fix while the watcher runs (the rename and its link rewrite racing the watcher's batch) were not checked by hand.
- Untraced tasks are computed in Rust with the trace's two task rules, so `trace.ts` and `doctor.rs` must change together (D-20261031-032416-q4dk).
