## Description
`S-board-sort` is ticked in the [spec](../spec.md) but not built: columns list tasks by file name, and a moved card goes to the end of its column (D-20261030-232042-h9dm). The [session panel](../done/20261031-005408-gv2i-session-panel.md) uses its own interim order until this exists (D-20261031-011606-s3pn); switching it over is [its own task](../inbox/20261031-012418-sf2u-session-panel-uses-the-board-sort.md).

Open points to decide and record: how priority, created and dependency order combine (for example a task never above a task it depends on in the same column), what happens with dependency cycles or unknown ids, and where a card lands after a move.

## Acceptance criteria
- [x] Every column orders its cards by priority (1 first, none last), then created, then id, with dependency order applied on top
- [x] The order is a pure TypeScript function with tests, used by the board
- [x] A moved card takes its sorted place instead of the end of the column
- [x] Cycles and unknown dependencies do not break the order

## Implementation notes
- Done: `sortTasks` in `src/lib/board.ts` with tests in `src/lib/board.test.ts`; `cardsOf` sorts each column with it. `moveCard` still appends to the column's tasks, and the cards show it at its sorted place. Rule recorded as D-20261031-021102-jyia; `S-board-sort` criteria updated.
- Open: none for this task. The session panel switch is the follow-up task.

> **Proposal:** `S-board-dnd` still says "The card moves at once and lands at the end of the column." It should now read "The card moves at once and takes its sorted place in the column (`S-board-sort`)." It is not in this task's `implements`, so it was left unchanged.

## Result
Columns on the board are sorted: priority 1 to 5 (none last), then `created`, then id, then file name, and a task comes after the tasks of the same column it depends on (D-20261031-021102-jyia). Dependencies outside the column, unknown ids and self dependencies are ignored; a cycle is broken at a task on it and no card is dropped. A dragged card shows at its sorted place right away, before the watcher batch, and also when a failed move puts it back.
- `npm run check` passes (tsc, biome, 257 tests). Not tried in the running app. Dragging was not checked by hand, and no DOM test covers the rendered order.
- `S-board-dnd` still says a moved card lands at the end of the column; see the proposal above.
