## Implementation notes
- Done: `src-tauri/src/domain/init.rs` and commands `init_project(repo_root)` and `add_images_to_gitignore(repo_root)`. Init writes the config from the built in template, then uses the config on disk, so an existing `docs/planner.yml` decides the planning root and columns. Files are opened with `create_new`, so nothing is overwritten; every path is reported as created or existing. Spec and braindump get a new id and today's date. A `spec/` folder means no `spec.md` is added. The report has `offer_gitignore` and `offer_planner_block`.
- The braindump text is a constant in `init.rs`, since `S-templates` lists no braindump template.
- Checks: `cargo test` (71 passed), `cargo clippy --all-targets`, `npm run check`.
- Split: showing the offers to the user moved to the [inbox task](20261030-220947-k07z-open-a-repository-and-run-init-from-the-app.md) for opening a repository, accepted by the user (D-20261030-224049-19xh).


## Result
`src-tauri/src/domain/init.rs` creates a project. In TypeScript: `initProject(repoRoot)` returns `{ created, existing, issues, offer_gitignore, offer_planner_block }`; `addImagesToGitignore(repoRoot)` returns whether `.gitignore` changed; the planner block is written with `writePlannerBlock(repoRoot)`.

- Order: `docs/planner.yml` first, then the config on disk decides the planning root and the column folders, then `spec.md` (from the `templates_dir` override if any), then `braindump.md`.
- Nothing is overwritten (`create_new`); a second init creates nothing. A `spec/` folder means no `spec.md`.
- Spec and braindump get a new id and today's date; their frontmatter is strict YAML (tested).
- An unreadable spec override falls back to the built in spec and appears in `issues`.
