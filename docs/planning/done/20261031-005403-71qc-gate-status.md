## Description
Implements `S-gate` in the [spec](../spec.md).

## Acceptance criteria
- [x] Shows whether the gate is met, using the `gate` keys in the config
- [x] Met when: no open blocking questions; every node not tagged `#later` is ticked and has at least one criterion; every rule is referenced by at least one node
- [x] When not met, lists each failing item with a link to it

## Implementation notes
- Done: `domain/gate.rs` with `gate_status` over `Spec` and `GateConfig`, command `gate_status(repo_root)`; `useGateStore` following `useSpecStore.spec`; `GateStatus` with an `onOpen(at)` prop; `gateChecks` in `src/lib/gate.ts`; tests in Rust and Vitest.
- Mounted in the spec view by the main session.

## Result
The gate is evaluated in Rust (`src-tauri/src/domain/gate.rs`, command `gate_status(repo_root)`) with the checks the `gate` keys turn on. Each failing item has a kind, a message and its file and line. `useGateStore` evaluates it again whenever the spec store reads the spec, and `GateStatus` in the spec view shows met or not met, the enabled checks and each failing item, which opens the spec at its line. This repository's spec meets the gate.
- Not tried by hand in the running app.
- The spec is read twice per reload: once by the spec store, once by `gate_status`.
