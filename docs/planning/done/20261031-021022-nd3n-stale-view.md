## Result
"Stale" in the view switch (Board | Spec | Stale) shows one list in three groups with counts: Stale (staleness flags), Blocked (tasks outside the terminal column with a blocking dependency, naming each id and its column), Broken (doctor findings). Each entry shows its kind, the task title, `path:line` and the reason, and opens the file in the editor at its line. The view keeps its own doctor report: it runs when the view is shown, 1 s after the last planning batch or outside markdown change while shown, and on "Check again" (D-20261031-033320-x1tn). Nothing is computed again; the three sources keep their rules.

Phase 4 exit test (`src/lib/stale-view.test.ts`): a generated project of 72 days, one task a day across inbox, next and done, a four-file spec, with `stale_after_days: 10` and `review_after_days: 45` and a fixed now. Every entry is checked against the data by rules written out in the test, every stale or blocked task is listed and fresh ones (including one exactly at the threshold) are not. Limits: the doctor's findings and the missing code paths are given as data, not computed from files on disk (the Rust checks have their own tests), and the project is built in memory, not as files.

Verified with `npm run check` (tsc, biome, 362 vitest tests). No Rust changed. Not tried in the running app: switching to the view, opening entries, and the doctor re-running after a change on disk.
